\begin{abstract}
Stateful agents can obtain provisional predictions from learned world models
and stronger evidence from isolated executable environments. The useful
research question is no longer whether to allocate test-time compute in
general, but whether a controller can acquire those two kinds of evidence
selectively while preserving repeated-run reliability under measured resource
and risk limits. We refine \method around that question. The target controller
selects a branch, evidence source, and stop decision; model, token, horizon, and
verification choices are later extensions that must be isolated empirically.
The implementation supplies a modular Gymnasium-compatible MCTS kernel,
resource accounting, multi-fidelity frontier valuation, verified replay,
simple discrepancy calibration, and binary learned routing. It does not yet
implement multi-model tree transitions, full joint routing, a hard
episode-level risk envelope, or an evaluated self-improvement loop. We
therefore make MCTS a secondary controller hypothesis: it must outperform a
capacity- and budget-matched non-tree policy after a sequential benchmark shows
oracle headroom. This research-status draft specifies that narrower hypothesis,
modern baselines, validity gates, and versioned evaluation requirements. It
reports no confirmatory benchmark result.
\end{abstract}

\section{Introduction}

Test-time computation has become an important axis of capability. A system may
sample several solutions, revise a trajectory, search a tree, call a stronger
model, or execute a candidate in a sandbox. Recent agent work studies parallel
sampling, sequential revision, dynamic planning, per-step allocation, and
agentic orchestration \citep{zhu2025agentcompute,paglieri2025whenplan,
lee2026catts,qin2026atlas,kim2026coding}. A broad ``learning when to think''
claim is therefore both timely and crowded.

MCTS remains a plausible substrate for adaptive allocation. Its central purpose is
to spend simulations non-uniformly across actions
\citep{kocsis2006bandit,browne2012survey}. Yet the simulation primitive is
normally fixed: each rollout is treated as if it came from the same environment
model at the same price. Neural MCTS changes the source of priors or values
\citep{silver2016alphago,silver2017zero,schrittwieser2020muzero}, but it does not
usually make simulator identity, executable evidence, and stopping a joint
branch-level decision. Explicit static and dynamic values of computation have
also already been studied within MCTS \citep{sezener2020voc}. Value of
computation or MCTS alone is not the novelty.

Model routing balances quality and cost \citep{ong2025routellm}; newer systems
jointly control model and output length \citep{xue2026r2router}, choose
metacognitive operations \citep{ma2026cot2meta}, or let an orchestrator gather
and synthesize evidence \citep{qin2026atlas}. The remaining distinction is
stateful and environmental: ``trust a prediction for routine branches, execute
two disputed branches against disposable state, then stop.''

The required resources are becoming practical. Language world models can
simulate agentic transitions \citep{zuo2026qwenagentworld,gu2025webdreamer},
while code- and database-backed environments provide more expensive executable
transitions and programmatic verifiers \citep{wang2026agentworld}. Stateful
tool benchmarks such as $\tau^2$-bench expose dual-control interactions and
verifiable world state \citep{barres2025tau2}. BrowserGym and WorkArena expose
web and knowledge-work tasks through gym-like interfaces
\citep{le2025browsergym,drouin2024workarena}. The research opportunity is to
test selective acquisition of executable evidence while holding the agent
harness and context policy fixed. Context management can itself drive
long-horizon gains \citep{lin2026context}, so it cannot remain an unrecorded
implementation detail.

The target \method separates an object-level environment action from a
meta-level evidence query. A query initially names a branch and either a
predictive or isolated executable source; a stop action commits to the best
current task action. The experiment constrains episode-level money, tokens,
wall time, executable calls, and action risk. Finer-grained model, token,
horizon, and verification choices are admitted only through separate,
identifiable extensions.

The intended contributions are:

\begin{enumerate}[leftmargin=1.25em,itemsep=0.2em,topsep=0.3em]
    \item a falsifiable hypothesis about branch-local acquisition of predictive
    versus independently verified executable evidence in stateful tasks;
    \item a controller comparison that treats MCTS as a candidate and requires
    capacity-matched non-tree, query-level, fixed, revision, and sampling
    baselines;
    \item an implemented Gymnasium-compatible kernel and evidence ledger whose
    present boundary is stated separately from target architecture; and
    \item an experiment contract that freezes harness, context, action,
    environment, grader, verifier, model, and resource-accounting versions.
\end{enumerate}

The contribution is \emph{not} the number of supported algorithms, value of
computation in MCTS, or generic ``when to think'' control. Classical variants
are reusable infrastructure. The proposed scientific claim concerns selective
predictive/executable evidence in a sequential, externally verified setting.

\section{Background and Related Work}

\subsection{Classical and Bayesian MCTS}

UCT applies upper confidence bounds to tree selection
\citep{kocsis2006bandit}. MCTS has since accumulated selection, expansion,
rollout, backup, parallelization, transposition, and domain-knowledge variants
\citep{browne2012survey}. Crazy Stone introduced soft selectivity and studied
mean, robust, and mixed backups \citep{coulom2006efficient}. Robust max uses the
value of the most-visited move, avoiding a noisy maximum over empirical values.

Posterior-sampling approaches represent uncertainty directly. Bayesian
reinforcement learning with MCTS can maintain Dirichlet transition beliefs
\citep{vien2013mcts}; posterior-sampling MCTS can use conjugate reward and
transition models or root-sampled dynamics
\citep{bai2018posterior}. \method uses these mechanisms as possible uncertainty
representations, but its compute policy also chooses \emph{which evidence
source} to sample.

\subsection{Neural search and language-model planning}

AlphaGo combines policy priors, value estimates, rollouts, and PUCT
\citep{silver2016alphago}; AlphaGo Zero removes rollouts and directly backs up a
policy-value network \citep{silver2017zero}. MuZero plans with a learned latent
dynamics model \citep{schrittwieser2020muzero}. More recently, AlphaZero-like
search has guided LLM decoding and supplied training targets
\citep{feng2024tsllm}; MCTS has also been used to collect preference data for
online optimization \citep{xu2025mctsep}. Tree-structured generative planning
continues to improve with inference compute \citep{yoon2025mctd}.

These results support search as a policy-improvement operator, but do not imply
that a tree is the best controller for agentic test-time compute. Recent coding
results obtain gains from trajectory summarization, tournament selection, and
sequential refinement without the proposed environment tree
\citep{kim2026coding}. A non-tree controller is therefore a required scientific
comparison rather than a weaker implementation baseline.

\subsection{Routing, metareasoning, and world models}

RouteLLM learns cost-quality routing from preferences
\citep{ong2025routellm}. R2-Router jointly selects a model and output-length
budget \citep{xue2026r2router}. Rational metareasoning studies the value of
computation (VOC), a long-standing limited-rationality concept
\citep{russell1991right}, for selective LLM reasoning
\citep{desabbata2025metareasoning}. Meta-BAMDPs extend metareasoning to
uncertain environments \citep{godara2026metabamdp}; recent metacognitive
controllers choose operations such as expansion, pruning, repair, and stopping
\citep{ma2026cot2meta}.

Dynamic planning agents choose whether to plan before individual actions
\citep{paglieri2025whenplan}, and CATTS adapts per-step sampling from vote
uncertainty in web agents \citep{lee2026catts}. ATLAS allows a stateful
orchestrator to gather further solver evidence, choose solver and reasoning
effort, stop, and synthesize \citep{qin2026atlas}. Together with explicit VOC
policies for MCTS \citep{sezener2020voc}, these systems invalidate novelty
claims based only on adaptive compute, stopping, or branch granularity.

The narrower \method hypothesis adds a specific evidence intervention:
selecting between a learned environment prediction and an independently
executed disposable state transition within a sequential task. Whether MCTS is
useful for that intervention remains empirical.

Language world models now predict state transitions in agent environments
\citep{zuo2026qwenagentworld}; WebDreamer uses an LLM as both world model and
value function for web planning \citep{gu2025webdreamer}. Agent World Model
constructs 1,000 code- and database-backed executable environments
\citep{wang2026agentworld}. This creates a useful asymmetry: learned models
provide cheap speculative breadth, while executable environments provide
costlier, higher-confidence evidence. C-MCTS also motivates low- and
high-fidelity simulators for safe planning, though it uses the high-fidelity
model offline to train a safety critic \citep{parthasarathy2024cmcts}.
\method instead proposes online, selective executable-evidence allocation.
Qwen-AgentWorld reports that uncontrolled simulation can harm some agent tasks,
which reinforces the need to measure decision impact rather than raw prediction
error alone \citep{zuo2026qwenagentworld}.

\subsection{Preference learning and causality}

Search can optimize a reward or preference model and can generate targets for
methods such as direct preference optimization
\citep{rafailov2024dpo,xu2025mctsep}. It does not eliminate the need to elicit
human objectives. Indeed, stronger search can exploit reward-model errors more
aggressively.

Selective routing creates observational data: expensive outcomes are observed
where the current router chose to query. Causal routing addresses decision
learning from such logged outcomes \citep{tsiourvas2025causalrouting}, while
doubly robust estimators combine propensity and outcome models
\citep{dudik2011doubly}. Causal world models may also improve long-horizon
language-agent planning \citep{gkountouras2025causality}. We adopt a narrow
position: causal evaluation is valuable for routing logs and structured tool
effects, but a universal causal world model is not a v1 prerequisite.

\section{Problem Formulation}

This section defines the target research intervention, not the complete current
API. The implemented router is binary (cheap versus accurate) with fixed token
and depth settings; verification is coupled to accurate evaluation. Its learned
target is absolute cheap--verified discrepancy rather than the decision utility
in Equation~\ref{eq:evc}.

\subsection{Object-level environment}

Let an environment be a finite-horizon MDP or information-state process with
states \(s \in \mathcal{S}\), task actions \(a \in \cA(s)\), rewards \(r\), and
transition kernel \(P\). In a partially observed setting, \(s\) denotes the
planner's information state, not inaccessible hidden state. A task policy
\(\pi_A\) ultimately selects a real action for the live environment.
In realistic tool environments, \(\cA(s)\) may be too large or structured to
enumerate. A proposal policy must then supply candidate actions together with
proposal provenance and cost; macro-actions or progressive widening become
part of the frozen controller condition.

We assume a portfolio \(\cM=\{m_1,\ldots,m_K\}\) of generative models. A member
may be a learned transition/value model, LLM, reversible Gymnasium environment,
executable sandbox, or verifier. Querying \(m\) at state-action pair \((s,a)\)
produces evidence
\[
o \sim p_m(o\mid s,a,b,d),
\]
where \(b\) is a token/sample budget and \(d\) is a rollout horizon. Evidence
may contain a next state, reward, value estimate, uncertainty, terminal flags,
and provenance. Each query incurs a resource vector
\[
g(o,m) =
(c_{\mathrm{money}},c_{\mathrm{token}},c_{\mathrm{time}},
 c_{\mathrm{accurate}},c_{\mathrm{risk}}).
\]

No portfolio member is declared ground truth by type. ``Accurate'' is a
relative fidelity label established empirically. Real outcomes and deterministic
verifiers have distinct provenance.

\subsection{Compute actions}

At meta-history \(h\in\cH\), containing the partial search graph and all
evidence, the compute policy \(\pi_C\) chooses
\[
c=(s,a,m,b,d,v)\in\cC(h),
\]
where \(v\) indicates requested verification. It may instead choose
\(\textsc{Stop}\), after which \(\pi_A(h)\) is executed.

The first confirmatory intervention restricts this space to branch, evidence
source, and stop. Token, horizon, verifier, context, and multi-agent-topology
control are later factors; jointly varying them in the first experiment would
prevent attribution.

The joint objective can be expressed as a constrained problem,
\begin{align}
\max_{\pi_A,\pi_C}\quad
    & \E\!\left[G(\pi_A;h_{\mathrm{stop}})\right] \\
\text{s.t.}\quad
    & \E\!\left[\sum_t g_j(c_t)\right]\le B_j
      \quad \forall j,                                      \label{eq:budget}\\
    & \Pr(\text{unsafe action})\le \epsilon ,
\end{align}
or as a Lagrangian utility
\[
J = \E\!\left[
G - \lambda^\top \sum_t g(c_t) - \kappa\,\mathrm{Risk}
\right].
\]
We report Pareto frontiers because a single set of multipliers can conceal
important quality-cost-risk trade-offs.
All constraints in the primary experiment apply to the complete task episode.
A fresh allowance per planner call is a diagnostic configuration, not an
episode-level budget guarantee.

\subsection{Discrepancy and value of computation}

For a cheap model \(m\) and executable reference \(H\), define paired
discrepancy
\[
\delta_m(s,a,h)=y_H(s,a)-\hat y_m(s,a,h).
\]
A discrepancy model predicts a distribution over \(\delta_m\), rather than
forcing cheap and executable estimates into one undifferentiated mean.

The ideal expected value of computation (EVC) is
\begin{multline}
\mathrm{EVC}(c\mid h)
=
\E_{o_c}\!\left[
U(\pi_A(h\cup o_c))-U(\pi_A(h))
\right]\\
-\lambda^\top \E[g(c)] .
\label{eq:evc}
\end{multline}
Exact EVC is generally intractable because it integrates future search changes.
We study analytic approximations, contextual bandits, and learned EVC models.
Before fitting such a model, the study must define a decision-level target and
show that an oracle selective policy has headroom over simpler controls.

\section{FidelityMCTS}

The following is target architecture. In the current implementation, outer
MCTS transitions are produced by one simulation model and the adaptive
portfolio evaluates already-created frontier actions. Portfolio
\texttt{next\_state} observations are not incorporated into the search graph.
Consequently the delivered component is multi-fidelity frontier valuation, not
yet multi-model transition search.

\subsection{Search graph}

We represent search as a state-action outcome graph. A state node stores state
identity and expansion metadata. An action edge stores
\(N(s,a),W(s,a),Q(s,a)\), prior \(P(s,a)\), optional Bayesian or AMAF
statistics, and model-indexed evidence. Outcome links represent stochastic
reward/next-state realizations. An iteration-local search path replaces a
canonical parent pointer, allowing transpositions without ambiguous backup.

This representation is important for multi-fidelity evidence. Querying an
accurate simulator does not overwrite a cheap prediction. Both remain attached
to the edge with model version, uncertainty, and measured cost.

\subsection{Two coupled policies}

The tree policy selects a promising frontier under ordinary MCTS statistics.
At that frontier, the compute policy repeatedly chooses evidence queries until
a stop policy fires. The evaluator aggregates current evidence, and a backup
operator propagates the resulting return. Thus UCT, PUCT, Thompson sampling,
direct neural evaluation, rollouts, and alternative backups remain injected
components rather than separate engine implementations.

Figure~\ref{fig:architecture} shows the system. The core design constraint is
that the live environment is never mutated by speculative search.

\subsection{Routing and stopping}

A reference score for a feasible compute action is
\begin{equation}
S_\theta(c,h)
=
\widehat{\Delta U}_\theta(c,h)
-\lambda^\top \widehat g_\theta(c,h)
-\kappa \widehat{\rho}_\theta(c,h),
\label{eq:routerscore}
\end{equation}
where \(\widehat{\Delta U}\) predicts decision improvement, \(\widehat g\)
resources, and \(\widehat\rho\) risk. In the target controller, unaffordable
route--action pairs are masked before scoring, and a hard risk ceiling is
enforced independently of the score. The router chooses
\(\arg\max_c S_\theta(c,h)\) only when the maximum is positive; otherwise it
stops. The current binary router instead selects a fidelity and then attempts to
reserve its quote; an unaffordable choice stops rather than trying the best
affordable alternative, and the current ledger has no hard risk ceiling.

Router features include search depth, value gaps, visits, predictive variance,
model disagreement, expected cheap-to-accurate discrepancy, novelty, branch
impact, reversibility, verifier availability, remaining budgets, and service
load. The action may be factorized into branch, model, token budget, horizon,
sample count, and verifier. This permits new portfolio members without
retraining a flat classifier from scratch.

These factorized choices are proposed, not delivered. Current learned-route
features include remaining-budget fields, but training only at the largest
SQLite budget makes those fields constant; search depth is also fixed at zero
in that fixture.

We include simple uncertainty-threshold and fixed-cascade policies as strong
engineering baselines. A learned router earns its complexity only if it
outperforms them under matched budgets.

\subsection{Evidence aggregation and backup}

An evidence aggregator produces a return distribution, not only a scalar.
Candidate implementations are:

\begin{itemize}[leftmargin=1.2em,itemsep=0.15em,topsep=0.25em]
    \item verified-first selection;
    \item Bayesian fusion with model-specific likelihoods;
    \item cheap prediction plus discrepancy posterior;
    \item ensemble disagreement with conservative lower bounds;
    \item direct neural value or mixed value/rollout estimates.
\end{itemize}

Only a simple verified-first/discrepancy path is currently exercised. Its
verified source is the first configured accurate-fidelity model, so heterogeneous
accurate sources require an explicit source-selection rule before evaluation.

The backup interface then chooses mean, distributional, robust, or mixed
propagation. For Crazy Stone compatibility,
\[
V_{\mathrm{robust}}(s)
= Q\!\left(s,\arg\max_a N(s,a)\right),
\]
and
\[
V_{\mathrm{mix}}(s)
=(1-\alpha_s)V_{\mathrm{mean}}(s)
+\alpha_sV_{\mathrm{robust}}(s),
\]
where \(\alpha_s\) can depend on visits and variance. Alternating-agent value
perspective is configured explicitly.

\subsection{Verified replay and proposed self-improvement}

Whenever executable or real evidence becomes available, the system stores
\[
(h,s,a,m,\hat y_m,\hat \sigma_m,
 c,p(c\mid h),y_H,g,\mathrm{versions}).
\]
The target record supports four distinct objectives:
\begin{align}
\mathcal{L}_{\mathrm{value}} &=
  \ell(\hat y_m,y_H),\\
\mathcal{L}_{\mathrm{disc}} &=
  \ell(\hat\delta_m,y_H-\hat y_m),\\
\mathcal{L}_{\mathrm{route}} &=
  -\widehat{\mathrm{EVC}}(c,h),\\
\mathcal{L}_{\mathrm{cal}} &=
  \ell_{\mathrm{proper}}(\hat p_m,y_H).
\end{align}
Updates are staged: collect with frozen versions, validate, train candidates,
evaluate offline, run randomized canaries, and promote only after quality,
calibration, cost, and safety gates pass.

Persistent replay, online discrepancy updates, audit logging, and estimator
utilities exist. No evaluated multi-round train--deploy--collect loop yet shows
improvement, stability, or resistance to selection bias. The SQLite OPE utility
uses selected verification events with an effectively deterministic target;
its ``online randomized'' comparison is the same conditional pass rate, so it
cannot validate router ranking.

Search can also produce visit distributions or verified pairwise rankings for
distillation and preference optimization
\citep{feng2024tsllm,xu2025mctsep}. This can replace the policy-optimization
step of some RLHF pipelines, but not human preference elicitation or reward
validation. Model-only outcomes remain labeled synthetic.

\subsection{Causal logging and evaluation}

Because the router decides what to verify, verified replay is selected data.
We log the probability of every chosen route and allocate bounded randomized
audit traffic. For a deterministic target router \(\pi\), a doubly robust
estimate has the form
\begin{multline}
\widehat V_{\mathrm{DR}}(\pi)
=\frac{1}{n}\sum_{i=1}^n
\left[
\hat r(x_i,\pi(x_i)) \right.\\
\left.
+\frac{\mathbf{1}\{c_i=\pi(x_i)\}}{p_i}
\left(r_i-\hat r(x_i,c_i)\right)
\right].
\end{multline}
Overlap, stable treatment definitions, and sensitivity analyses are required.
Causal claims are limited to interventions the system can define and support.

\section{Software Architecture}

\subsection{MonteCarloGym kernel}

\mcg provides a stable agent interface:
\begin{center}
\small\texttt{action = agent.compute\_action(}\\
\small\texttt{sim\_env, observation)}
\end{center}
The user then calls the normal Gymnasium
\(\texttt{env.step(action)}\) and passes the real transition to
\(\texttt{agent.observe}\). Gymnasium standardizes environment interaction
\citep{towers2024gymnasium}, but generic generative-model protocols keep the
kernel usable outside Gym.

The environment wrapper currently supports native snapshot/restore or safe deep
copy. Clone-state, deterministic event reconstruction, and external-model
adapters are target strategies, not delivered implementations. A
transaction restores internal state, wrapper state, RNG streams, episode
counters, and terminated/truncated flags even after exceptions. Environments
that cannot satisfy this contract fail fast.

The search graph stores statistics on action edges and represents stochastic
outcomes explicitly. Transposition tables use adapter-provided state keys. Tree
reuse re-roots only after a matching real transition and invalidates
incompatible model or state versions.

policy, backup, model portfolio, compute router, stop policy, reward source,

\subsection{Deployment and open-source surfaces}

The dependency-light Python core is packaged for a future PyPI release; this
draft does not assert that it is published. A containerized planner service and
HTTP/gRPC/MCP interfaces are also planned rather than implemented. Thin
TypeScript adapters should expose an explicit
\texttt{plan\_and\_execute} operation rather than assume a late tool hook can
control earlier model selection. Router and discrepancy checkpoints, model
cards, and permitted datasets can be released through model/data hubs.

Any future production deployment should separate search coordinators, batched model gateways,
simulator workers, replay storage, tracing, and asynchronous training. Every
request has a budget envelope and idempotency key. Speculative execution uses a
sandbox or dry run; irreversible or externally visible actions require an
approval boundary.

\section{Experimental Protocol}

No confirmatory hypothesis or seed set is currently registered. A fresh study
first tests whether a selective predictive/executable policy has oracle
headroom on a genuinely sequential task. Only then does it compare end-to-end
controllers under the same task distribution, action proposer, context policy,
harness, portfolio, external-action policy, and hard episode budget. The task
instance is the independent unit; model samples, candidate orderings, and
random seeds within one task are repeated measurements.

\subsection{Baselines}

Required comparisons are: direct/no-search; cheap-only; accurate-only; a fixed
budget or top-\(k\) cascade; random escalation matched to executable-call rate;
an uncertainty threshold; a query-level router; joint model/length routing; a
capacity-matched direct non-tree adaptive controller; parallel best-of-\(N\)
with listwise verification; sequential revise/reflect; native reasoning-effort
control; verified-state management; and the MCTS controller. Agentic
test-time-compute work shows that sampling, revision, diversity, aggregation,
and trajectory reuse are consequential controls
\citep{zhu2025agentcompute,kim2026coding}. Multi-agent decomposition is included
only where the task supports parallelism and only with matched cost.

An oracle is a design diagnostic, not automatically an upper bound. If
portfolio order or affordability constrains it, it is labeled a
``budget-limited counterfactual.'' MCTS is evaluated only when a truly
budget-informed oracle establishes headroom.

\subsection{Metrics and primary analysis}

The primary quality measure is terminal task state from an independent,
versioned verifier, not the agent's completion claim. False-success work shows
that confident completion can disagree sharply with environment state
\citep{advani2026false}. We report pass@\(k\), pass\(^{k}\), verifier
false-positive/negative rates, stale-state errors, assertion coverage,
side-effects, and infrastructure failures separately from agent failures.

Resource measures are real money, input/output/context tokens, CPU/GPU time,
executable calls, concurrency-adjusted wall time, memory, approval requests,
and action risk. We report medians and tails/CVaR in addition to means.
Diagnostics include value error, interval coverage, calibration, discrepancy,
escalation precision/recall, stopping regret, and offline-evaluation bias.

The primary result is a repeated-run verified-success--cost--risk frontier over
prespecified episode budgets. We report paired hypervolume differences under a
frozen reference point, success at matched cost, cost at matched success, and
area under the budget-performance curve. A single weighted aggregate is
secondary.

\subsection{Hypotheses and ablations}

The candidate primary hypothesis is that branch-local selection between
predictive and isolated executable evidence improves the verified-success--cost
frontier over the strongest fixed, query-level, and direct non-tree controls.
The conditional MCTS hypothesis is that the tree controller adds improvement
over a capacity- and budget-matched non-tree controller. Secondary candidates
test decision-aware discrepancy versus raw prediction error, and
non-inferiority of learned stopping at lower resource use. Replay improvement
and off-policy router ranking remain future questions until a valid multi-round
loop and overlapping randomized behavior policy exist.

Ablations must alter one operative mechanism. The SQLite labels
``no verification'' and ``cheap only'' currently coincide; ``no discrepancy''
still updates the discrepancy model; and ``no tree reuse'' is inapplicable.
Those labels cannot support causal component claims and must not be copied into
the fresh protocol.

\subsection{Statistics and artifacts}

Task instances are paired across methods. Resampling and inference preserve
task/family clusters and never flatten seeds or budget rows into independent
observations. Sample sizes follow a tracked pilot with raw outputs and an
auditable effect-size lineage. The confirmatory plan prespecifies paired
hypervolume inference, task-stratified bootstrap intervals, multiplicity
control, and an explicit non-inferiority margin. The existing SQLite candidate's
``32 repetitions'' are four tasks under eight candidate-order permutations and
do not provide 32 independent units; its embedded power calculation is
invalidated.

Each run releases its resolved configuration, source revision, artifact hashes,
environment, harness, context, action, grader, verifier, and model versions,
reasoning settings, seeds, structured decision and episode ledgers,
per-episode JSONL, failures, and analysis. Reanalysis verifies every input and
manifest hash.
Provider and infrastructure non-determinism are measured with repeated trials
across time/load strata. All current local fixtures remain software or mechanism
diagnostics, not reported confirmatory results.

\section{Discussion}

\subsection{Why this may work}

The hypothesis exploits two forms of heterogeneity. First, learned-model error
is structured: a predictive source may be adequate for routine transitions but
fail on novel, ambiguous, or safety-critical states. Second, evidence has
decision-dependent value: an additional observation matters only when it can
change an action or reduce unacceptable risk. EVC gives a language for the
second effect, but raw prediction discrepancy is not itself EVC.

A tree may add a third form---unequal branch importance---but only if there is
enough branching, horizon, and affordable executable headroom. If a direct
controller captures the same evidence boundary, MCTS overhead is unjustified.

\subsection{Relationship to RLHF}

Predictive search can serve as policy improvement at inference time or produce
targets for distillation/preference optimization. In this limited sense it can
replace ``the RL step'' of an alignment pipeline. It cannot determine what
humans want, validate a reward model, or guarantee safety. Search may amplify
reward hacking by finding adversarial high-score trajectories. We therefore
retain reward provenance, component scores, uncertainty penalties, independent
verifiers, and human approval for consequential actions.

\subsection{Why off-policy evaluation is deferred}

Off-policy correction addresses a concrete problem: the next router is trained
and selected from outcomes acquired by the previous router. Randomized audits
and propensity-based estimators can reduce selection bias, but only with stable
treatments, overlap, and an independent online target. The current SQLite
analysis does not meet that bar. Structured causal world models may help where
variables are stable and intervenable; universal causal modeling is outside the
first experiment.

\section{Limitations and Risks}

\paragraph{EVC estimation.}
The value of a computation depends on counterfactual future search, making
supervision sparse and policy-dependent. Simple threshold routers may remain
competitive. Oracle-router experiments are needed to quantify available
headroom.

\paragraph{Controller necessity.}
MCTS can be the wrong abstraction when actions are open-ended, proposal quality
dominates, or horizon is short. Capacity-matched non-tree controllers, action
proposal costs, and an oracle-headroom gate are necessary to distinguish a
search benefit from routing alone.

\paragraph{High fidelity is not ground truth.}
Executable synthetic environments can omit production behavior. Browser
sandboxes can differ from live sites. We must report simulator-real discrepancy
and use real outcomes only where safe and consented.

\paragraph{Verifier and benchmark drift.}
Programmatic graders can be incomplete, LLM judges can follow surface cues, and
benchmark releases can alter task semantics. Verifier identity, assertion
coverage, benchmark and grader versions, false-positive/negative audits, and
environment-state evidence are part of every result.

\paragraph{Harness and context confounding.}
Agent harnesses and context management can materially change long-horizon
outcomes \citep{lin2026context}. The primary comparison holds them fixed and
logs them. Jointly optimizing context or agent topology is later work.

\paragraph{Distribution shift and feedback loops.}
Verified replay is concentrated near the router's boundary. Without exploration
and correction, the system may become confidently blind elsewhere. Jointly
updating world model and router can destabilize targets.

\paragraph{Safety and security.}
Tree search can generate many tool actions, increasing prompt-injection and
credential exposure. Speculation must be isolated; logs must redact secrets;
side effects must be approval-gated. A sandbox reduces but does not eliminate
risk.

\paragraph{Overhead.}
Maintaining uncertainty, discrepancy, traces, and routing can cost more than it
saves on easy tasks. No-search and fixed-cascade baselines are therefore
essential.

\paragraph{Research breadth.}
The target architecture spans MCTS, routing, world models, causal evaluation,
and agent systems. The first eligible study fixes one predictive/executable
pair and one evidence action. Joint model/token/depth/verifier routing,
multi-agent topology, and self-improvement are explicitly deferred.

\paragraph{Current evidence.}
The implementation has no eligible sequential study. SQLite Phase 5A is a
one-decision instrumentation diagnostic with four task templates,
non-independent order permutations, non-isolated ablations, and a
budget-limited ``oracle.'' It cannot support the proposed hypothesis.

\section{Open-Source Plan and Broader Impact}

The current codebase separates a minimal \mcg kernel from optional Gymnasium
support. PyTorch, Transformers, browser, service, registry, and archival-release
surfaces are plans, not delivered products. Any public research artifact must
retain its exact protocol, inputs, hashes, and validity status.

Positive uses include lower-cost planning, reproducible MCTS research, safer
sandbox-first agents, and better resource accounting. Negative uses include
more capable automation of harmful tasks and reward-model exploitation.
Adapters should default to read-only/dry-run operation, use scoped credentials,
and expose both safety and cost telemetry. Training data and model-generated
traces must be labeled by provenance.

\section{Conclusion}

The fit-for-purpose review narrows \method from generic joint test-time-compute
control to selective acquisition of predictive and executable evidence in
stateful agent tasks. The premise remains plausible and increasingly practical,
but broad novelty has been overtaken by dynamic planning, routing, and agentic
orchestration work. The classical kernel and evidence infrastructure remain
useful; the old empirical claim does not.

The next paper succeeds only if a fresh, versioned sequential study first shows
oracle headroom, then improves repeated-run independently verified success
against modern matched-budget controls. MCTS receives a separate conditional
test against a capacity-matched non-tree controller. Failure at either gate is
a result and a reason to simplify or redirect the project.

\section{API Contracts}

\paragraph{Generative model.}
A model exposes stable identity, fidelity, a conservative pre-call resource
quote, and an evaluation method. Its observation includes value, variance,
measured cost, tokens, latency, risk, optional next state, terminal flags, and
metadata.

\paragraph{Planner.}
The target planner receives a state, model portfolio, hard episode envelope,
remaining resources, and seed. It returns a task action, predicted value,
measured decision and cumulative episode usage, and an auditable structured
trace. Current APIs enforce planning-call rather than episode budgets.

\paragraph{Reward source.}
Rules, environment rewards, preference models, humans, and verifiers implement
one scoring protocol. A score carries scalar value, named components,
verification status, source, version, assertion coverage, and retained evidence.
The richer verification fields are a target schema extension.

\paragraph{Replay.}
A verified record pairs cheap predictions with executable or real outcomes and
includes router propensity and full environment, prompt, model, verifier, and
resource versions. Synthetic, executable, and real provenance are never
collapsed. The current replay schema is narrower and must be migrated before a
confirmatory run.

\section{Implementation Invariants}

\begin{enumerate}[leftmargin=1.4em,itemsep=0.15em]
    \item Snapshot/restore reproduces environment and RNG state.
    \item Planning cannot mutate the live environment.
    \item Edge visits equal completed backups.
    \item Configured planning-call resource limits are never exceeded, including failures.
    \item Termination and truncation remain distinct.
    \item Robust max selects the most-visited child.
    \item Imaginary Bayesian transitions do not update the real root belief.
    \item RAVE direct and AMAF updates are not double counted.
    \item Accurate evidence augments rather than silently overwrites provenance.
    \item Every learned route used for causal evaluation has a logged propensity.
\end{enumerate}

Hard episode budgets, a risk ceiling, feasible-action masking, and complete
versioned replay are target invariants, not current guarantees.

\section{Claim Readiness}

Before replacing proposal language with empirical claims, require: demonstrated
oracle headroom; a sequential executable task; independent terminal-state
verification; a frozen harness, context policy, action proposer, environment,
grader, verifier, model, and reasoning configuration; hard episode budgets;
modern matched-budget and capacity-matched non-tree baselines; isolated
ablations; independent task units and clustered analysis; repeated reliability,
tail-risk, verifier, and infrastructure reporting; full artifact hashes; and a
fresh protocol frozen before confirmatory data collection.
